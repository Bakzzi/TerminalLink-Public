- 공백이 포함된 소스 경로에서 Windows self-contained 배포 빌드

빌드/실행 코드의 검증 기준 커밋은 `582a207c1041cb54f2bab550070adc8949ab8d70`입니다. 이후 변경은 문서, 공개 자료 검사, 기존 파일함 CLI를 호출하는 스크립트입니다. 마지막 스크립트는 구문 검사했고, 사용자의 실제 파일을 공유하는 실행은 하지 않았습니다.

2026-10-13 PC 0.9.34 추가 검증: 빈 줄이 있는 여러 줄 질문을 원본 대화와 비교할 때 문단 끝에서 잘리는 문제를 수정했습니다. 같은 공통 로직을 기존·신규 로컬 탭에 적용합니다. 전체 질문, 빈 줄 뒤 불일치, 짧은 동일 접두사, 중복 원본, 미전송 입력, 작업 상태, 접힌 질문과 도구 출력, 구조화된 요청 답장을 포함한 합성 검사 30개와 루프백 TLS 검사를 통과했습니다. 별도 비공개 진단 자료의 이전 실패 사례 4개 및 실행 중인 로컬 원본 대화도 읽기 전용으로 확인했습니다. 실제 터미널에 테스트 입력을 보내지 않았습니다.

Android 코드와 통신 형식은 변경하지 않아 이번 수정에서 APK 빌드·에뮬레이터 검사는 반복하지 않았습니다. 휴대폰 화면에서의 실제 확인은 PC 원본 읽기 검사와 별도입니다. 개인 대화·원본 경로·진단 캡처는 Git에 포함하지 않습니다.

PC 0.9.34의 개별 읽기 검사는 충분하지 않았습니다. 이후 화면 위에 고정된 질문 아래로 발화 표시가 없는 과거 답변이 나타나면, 그 답변을 질문에 합쳐 기존 원본 연결을 해제하는 회귀가 확인됐습니다. 0.9.35는 완전한 원본 질문과 일치하는 기존 비교 형태를 유지하면서 빈 줄을 포함한 여러 줄 질문도 비교합니다. 서로 다른 두 원본에 일치하면 여전히 연결을 거부합니다. 넓은 터미널에서 긴 답변이 한 줄에 표시되는 경우에도 같은 원본 답변의 충분한 본문 증거를 확인합니다.

추가 합성 검사는 고정 질문 아래의 과거 답변, 넓은 화면의 단일 답변 줄, 원본 답변 없는 짧은 질문 거부를 포함합니다. 개발용 `--delivery-read-probe <folder>`는 별도 루프백 인증서·등록 정보·파일함을 사용해 실제 이벤트 처리와 텍스트 전송 경로를 검사합니다. 읽기만 수행하고 현재 터미널에 입력하지 않으며 운영 휴대폰 연결도 사용하지 않습니다. 진단 자료와 보호된 연결 메타데이터는 Git 대상이 아닙니다.

0.9.35는 합성 검사 33개와 루프백 TLS 검사를 통과했습니다. 실행 중인 네 탭(로컬 3개·SSH 1개)을 같은 이벤트 허브에서 읽고, 정방향·역방향으로 7회 선택하면서 매번 준비된 원본 대화 전체가 암호화 연결로 수신되는 것을 확인했습니다. 기존에 검증됐던 보호된 연결 메타데이터를 재사용하되, 현재 프로세스·원본 소유자·기록 연속성 검사를 다시 통과해야 복원되도록 했습니다. 작업 로그만 보이는 화면에서 처음 대화를 추측해 연결하는 방식은 추가하지 않았습니다. 실제 휴대폰 UI 검사는 별도이며 이번에 수행하지 않았습니다.
