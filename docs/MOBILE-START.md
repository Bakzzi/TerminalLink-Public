# 새 로컬 Codex 대화 시작

PC 연결 프로그램 0.9.42와 Android 0.9.41부터 지원한다. Desktop 배포와 별개로 두 구성 요소를 함께 갱신해야 한다.

첫 질문 전에는 원본 대화가 아직 없을 수 있다. 명확한 Codex 시작 화면, 빈 입력칸, 동일 Windows 사용자·콘솔·Codex 프로세스 시작 시각을 확인한 경우에만 `source=start`, `readState=empty` 상태를 전달한다. 모바일은 이를 오류 대신 새 대화 안내로 보여 준다. 이는 원본 대화가 아니며 요청 답장·첨부·알림 권한을 부여하지 않는다. 탭 제목이나 폴더 이름으로 분기하지 않는다.

휴대폰은 기존 인증 연결과 허용된 터미널 ID를 사용해 `notificationInput`, `kind=startMessage`를 보낸다. 서버는 같은 초기 상태를 다시 확인하고, 붙여 넣은 글과 프로세스 식별자를 재확인한 뒤 Enter를 한 번만 보낸다. 기존 초안·요청 화면·셸·다른 세션에는 보내지 않는다. 메시지 전송 중에는 기존 입력 잠금·실패 복구를 사용한다. `/` 명령은 터미널 보기에서 실행한다.

전송 전후의 실제 소유 원본 목록을 비교하고, 새 원본 또는 이전에 비어 있던 원본의 첫 질문과 화면 근거가 유일하게 일치할 때만 연결한다. 이전 대화나 중복 후보를 임의로 선택하지 않는다. Enter 이후 원본 연결이 지연돼도 입력을 재전송하지 않는다. 모바일에는 확인된 보낸 글을 임시 표시하고 실제 원본이 도착하면 중복 없이 교체한다. 시작 화면을 벗어난 뒤 원본을 기다리는 상태는 최대 30초이며, 계속 읽지 못하면 오류를 표시한다. 이 대기 상태에서도 추가 전송은 차단한다.

기존 로컬·SSH 대화는 기존 원본 식별·전송 경로를 유지한다. 원격 SSH의 첫 질문 이전 화면은 이 로컬 시작 경로로 위장하지 않는다. 대화 기록 길이를 제한하거나 터미널 화면 일부를 대화 원본으로 대신 표시하지 않는다.

검증 범위는 최초 전송 보호 합성 검사, 실제 Android 전송 클래스의 JVM 검사, 기존 요청·알림·루프백 인증 검사, 양쪽 배포 빌드, 실제 초기 콘솔의 읽기 전용 상태 확인이다. 사용자 작업에는 테스트 질문을 입력하지 않는다. 휴대폰 설치와 실제 첫 질문 전송은 별도 확인 사항이다.
