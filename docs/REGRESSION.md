# 회귀 검증

`tools/test.ps1`은 운영 터미널과 등록 정보를 사용하지 않습니다.

- PC: 표시 변환이 원본을 바꾸지 않음, 복수 질문 답장·잘못된 envelope, citation 코드 예시 보존, 전체/증분 대화 전송, 긴 UTF-8 내용의 청크 복원, 합성 Codex 기록의 추가 읽기.
- 원격 기록: 실제 Python 읽기 코드를 합성 `/proc`·기록 파일로 실행합니다. 답변만 보이는 화면, 다른 SSH 연결·작업 디렉터리·지원하지 않는 생성 경로 거부, 편집기에서 시작해 현재 TUI에서 재개한 기록, 중복 답변의 모호성, 서로 다른 메시지를 합친 증거 거부, 접기 안내 제외, 기존 질문 연결 및 증분·재시작 검증을 포함합니다.
- TLS: 미등록/누락/잘못된 키, 틀린·만료된 등록 토큰, 최초 승인, 재접속, 서버 pin 불일치, 기기 등록 해제, 과대 메시지 거부.
- Android JVM: 실제 요청·알림 코드를 운영체제 대역과 실행. 일시 읽기 실패 시 질문·선택·초안 유지, 재확인, 완료/다른 요청 처리, 연속 알림 답장과 성공·실패 처리. 복수 원본 질문의 첫 답변 후 다음 질문 전환, 이전 질문의 늦은 응답 격리, 현재 Shift-arrow 및 이전 Alt-arrow 요청 열기·첫/마지막 질문 안내 인식을 포함합니다.
- 답장 알림 정리: 원본 사용자 답장의 순번, 직접 이벤트·재접속 snapshot·백그라운드 푸시, 다른 탭/PC 및 새 답변 보존, 지연·역순 재전송 방지, 전송 실패와 SystemUI 전송 중 상태, 미응답 요청 보존, 마지막 알림의 요약 제거.
- 모바일 안 읽은 답변: 로컬·SSH·푸시 수신, 알림을 꺼도 파란 점 유지, 보이는 답변/성공한 답장만 읽음 반영, 다른 탭·새 답변 보존, 재연결·재실행·옛 알림 기록 정리 후 재점화 방지. 실제 폰에서는 탭 목록의 파란 점과 탭 수, 탭 선택·초안·대화 스크롤이 유지되는지 별도 확인합니다.
- 전송 상태: 전송 중 중복 제출 차단, 성공 직후 메시지 표시, 실패·시간 초과·연결 종료 시 원문 유지, 무관한 요청 응답 무시, 원본 선도착/후도착 및 동일 문장 연속 전송의 중복 방지. PC 입력 검사는 원본 불일치와 기존 터미널 초안이 있을 때 실제 키를 보내지 않는지도 포함합니다.
- 빌드: PC self-contained EXE와 서명 APK. 에뮬레이터 없이 수행합니다.

변경하지 않은 범위에 대해 같은 검사를 반복하지 않습니다. 합성 검사 통과를 실제 폰의 설치·UI·OEM 절전 동작이 검증됐다는 의미로 사용하지 않습니다. 실기기 확인에는 새/기존 탭, 읽는 중 네트워크 끊김, 연속 알림 답장, 첨부, 앱 전환을 포함합니다.

개인 대화/캡처는 fixture로 커밋하지 않습니다. 실패를 재현할 때 원인을 보존한 합성 질문·ID·경로로 바꿉니다.

PC self-test의 암호화된 임시 인증서는 `build/tests/pc/test-identity-*` 아래에만 만들어집니다. 배포·Git 대상이 아니며 운영 등록 정보를 재사용하지 않습니다.

요청 관리 구조의 전환에는 [요청 생명주기 개선안](REQUEST-LIFECYCLE.md)의 사례별 통과 기준을 사용합니다. 이 설계에 적힌 계획을 현재 통과한 검사로 집계하지 않습니다. 검사 기대값은 실제 지원할 사용 방식에서 정하며, 현재 구현의 거부 조건을 그대로 정상 결과로 옮기지 않습니다.
