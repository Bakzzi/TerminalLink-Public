# Desktop client boundaries

- Follow the root rules and the desktop README. This project must be removable without reverting the mobile application or its PC connector.
- Product intent: a Windows conversation client with a Codex-like layout, existing terminal sessions, questions, final answers, request popups, attachments and optional terminal viewing. Preserve the `>_<` mark.
- Keep acquisition/identity in the connector contract and presentation in this client. Do not create another screen-to-conversation parser or use visible terminal fragments as full chat history.
- Use `TerminalLink-Desktop.exe`, `dist/Desktop/` and a distinct `TerminalLinkDesktopPreview` application data namespace. Synthetic profiles use additional per-run directories. Do not copy private live identity or registration files into test profiles.
- Start UI work with synthetic records. Preview failures, app exit, window close and tray actions must not stop user terminal sessions or the production connector.
- The existing server permits one paired phone and disconnects a previous active socket. Desktop therefore uses linked connector components locally, with same-user/session/PID/start-time checks and inherited private worker pipes; it never connects as the phone or starts another TCP server. It reads the existing protected SSH read profile without copying/changing registration. All writable caches and attachments use the desktop namespace. See README for the three desktop-only host adapters.
- Keep view state per conversation. Preserve selection, draft and scroll position across tab switches and tray restore. No arbitrary conversation-history cap; rendering virtualisation or transport chunking must not delete or truncate stored history.
- A transient refresh error preserves already displayed verified content and request drafts, with a visible stale/error state. A confirmed identity change must never display another conversation as the current one or send to the old target.
- Ordinary text targets the selected native terminal, independently of conversation-history availability (user correction 2026-10-16). Recheck the selected native console PID/start time, append without clearing its draft, use the ordered native writer and send Enter once. Do not require history matching or screen-text readback after pasting. Request answers and attachments keep their separate original-record verification. Never use a successful text send as evidence for a history binding.
- `Open in terminal` means the same existing customized Windows Terminal window/tab. No replacement shell, embedded host or Codex desktop forwarding.
- User correction 2026-10-25: ordinary conversation and terminal text share the ordered native writer and acknowledgement. Screen/cursor/empty-draft/history checks must not veto ordinary input. The selected console PID/start-time is the delivery authority. Append without clearing a draft, as terminal input does. Request/notification/attachment routes remain independently verified.
- Validation is scoped and sequential: source boundary check, affected synthetic checks, desktop build and one necessary preview check. No Android build/emulator unless a separately scoped shared-contract change actually requires it.
- Before every build/commit run `python desktop/check-boundary.py`. Future desktop build entry points must call it and fail on a nonzero exit.
- No automatic deployment, startup registration, firewall changes, pairing changes, terminal ownership changes or main-branch merge as a side effect of building or launching a preview.
- User-authorized automatic updates are a separate publication step after validation and commit/push: use `desktop/publish-update.ps1`, following `desktop/AUTOMATIC-UPDATES.md`. Do not ask the user to close a working app for each release; the installed updater defers while active/drafting/sending. Bootstrap installation still uses normal close and preserves all native terminal sessions.
